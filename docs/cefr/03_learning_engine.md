# เครื่องยนต์การเรียน: กติกาที่อยู่เบื้องหลังคอร์ส (16 พ.ย. 2569)

เอกสารนี้ตอบคำถามว่า "ระบบตัดสินใจอย่างไร": ข้อไหนกลับมาเมื่อไร วันนี้ได้ทำอะไร ผลวัดระดับแปลว่าอะไร ความพร้อมคิดจากอะไร และเซิร์ฟเวอร์กับเครื่องผู้เรียนคุยกันอย่างไร
**คำนิยามที่แท้จริงคือโค้ด:** `engine/engine.mjs` (ฟังก์ชันล้วน ใช้ไฟล์เดียวทั้งเบราว์เซอร์และ Edge Function) · ค่าปรับได้ทั้งหมด `engine/config.json` · พฤติกรรมถูกตรึงด้วย `tests/test_engine.mjs` (41 กรณี)
ผู้ที่มาทำต่อ: **ห้ามเขียนตรรกะเหล่านี้ซ้ำในหน้าเว็บหรือฟังก์ชัน** ให้ import จากไฟล์เดียว · จะเปลี่ยนกติกาให้แก้ที่ config หรือ engine พร้อมเทสต์ แล้วบันทึกเหตุผลที่นี่

## 1. เวลา
- ทุกอย่างคิดตามเวลาไทย (UTC+7) และ**วันใหม่เริ่ม 03:00 น.** ครูที่เรียนหลังเที่ยงคืนยังนับเป็นวันเดิม (`dayNo`)
- สัปดาห์เริ่มวันจันทร์ (`weekStart`)

## 2. การทบทวนตามเวลา (`srsUpdate`)
| เหตุการณ์ | ผล |
|---|---|
| เจอครั้งแรกแล้ว**ผิด** | กลับมาพรุ่งนี้ (ขั้น 1) |
| ตอบถูกเมื่อถึงกำหนด | เลื่อนขั้น ระยะ 1 → 3 → 7 → 16 → 35 วัน |
| ผ่านขั้น 3 (ถูก 2 ครั้งที่เว้นระยะ) | นับว่า "ได้แล้ว" (`mastered`) แต่ยังทวนต่อจนครบขั้น แล้วทวนทุก 90 วัน |
| เจอครั้งแรกแล้ว**ถูก** | ยังไม่นับว่าได้ ตรวจซ้ำครั้งเดียวที่ 14 วัน ถูกอีก = ได้แล้ว · ผิด = นับเป็น "หลุด" เริ่มขั้น 1 |
| ตอบถูก**ก่อน**ถึงกำหนด (เช่น ในฝึกเพิ่ม) | ไม่เลื่อนขั้น กันการกดซ้ำเพื่อปั๊มความคืบหน้า |
| ตอบผิดเมื่อใดก็ตาม | กลับขั้น 1 พรุ่งนี้ · ถ้าเคยผ่านมาก่อนนับ "หลุด" +1 |
| หลุดครบ 3 ครั้ง (`isLeech`) | หยุดวนซ้ำเฉย ๆ: หน้าเว็บพาไปอ่านบทเรียนย่อของหัวข้อนั้นก่อน แล้วจัดเข้ากลุ่มในสมุดข้อผิด |

เหตุผลของตัวเลข: ระยะสั้นช่วงแรกเพราะคอร์สยาวแค่ 12 สัปดาห์ ข้อที่ผิดในสัปดาห์ 1 ต้องวนครบทุกขั้น (62 วัน) ก่อนชุดวัดผลครั้งที่ 3
**ชุดข้อความ (บทอ่าน บทฟัง ข้อความมีช่องว่าง):** ไม่วนชุดเดิมซ้ำ เพราะผู้เรียนจำเนื้อเรื่องได้ ถ้าผิดในชุดใด ระบบจัดชุด**อื่น**ของทักษะและหัวข้อเดียวกันใน 3–7 วัน และชุดเดิมจะกลับมาได้หลัง 21 วันเท่านั้น → คลังต้องมีชุดสำรองต่อหัวข้อ (ข้อกำหนดถึงผู้เขียนเนื้อหา)

## 3. การประกอบเซสชัน
| ขั้น | ที่มาของข้อ |
|---|---|
| 1 ทบทวน | `pickReview`: ข้อที่ถึงกำหนด เรียงเลยกำหนดนานสุดก่อน แล้วหลุดบ่อยสุด สูงสุด 8 ข้อ ไม่ซ้ำกับข้อของวันนี้ · ตั้งแต่สัปดาห์ 2 ถ้าข้อถึงกำหนดไม่เต็ม เติม**ข้อใหม่จากหัวข้อของสัปดาห์ก่อน ๆ** ได้ไม่เกิน 2 ข้อ (นี่คือการสลับหัวข้อ) |
| 2 เรียน | `lesson` + `check` 2 ข้อของวันนั้นจากไฟล์คอร์ส |
| 3 ฝึก | `practice` ของวันนั้นตามลำดับในไฟล์ (ผู้เขียนเรียงจากง่ายไปยากแล้ว) |
| 4 ใช้ · 5 ปิด | จากไฟล์คอร์ส |

- เซสชันสั้น 5 นาที = ขั้น 1 อย่างเดียว (สูงสุด 8 ข้อ) นับเป็นวันที่ได้เรียน แต่ตัวชี้บทเรียนไม่ขยับ
- **จังหวะ:** 20 นาที = 1 เซสชันต่อวัน · 10 นาที = ครึ่งเซสชัน (วันแรกขั้น 1–2 วันถัดไปขั้น 3–5) · 40 นาที = 2 เซสชัน · ตัวชี้ความคืบหน้าคือ (สัปดาห์ วัน ขั้น) จึงออกกลางคันแล้วทำต่อได้ทุกจังหวะ
- **วันจบ** (`projectFinish`) คำนวณใหม่ทุกครั้งจากเซสชันที่เหลือ ไม่มีการสะสม "งานค้าง" ไม่มีบทลงโทษ
- **หายไป 7–29 วัน** (`gapMode` = comeback): เซสชันแรกเป็นทบทวนสูงสุด 10 ข้อ + ทวนบทเรียนล่าสุด 5 ข้อ แล้วจึงเดินต่อ · **หายไป ≥ 30 วัน** (replace): เสนอให้ทำชุดวัดผลล่าสุดใหม่เพื่อตั้งต้นความพร้อม (ไม่บังคับ)
- **เซสชันซ่อม** (`remedialTopic`): หลังชุดย่อยวันที่ 6 หัวข้อที่ถูกต่ำกว่า 60% (มีข้อมูล ≥ 3 ข้อ) ต่ำสุด 1 หัวข้อ ถูกแทรกก่อนวันที่ 1 ของสัปดาห์ถัดไป = บทเรียนย่อเดิมแบบย่อ + ข้อสำรอง 8 ข้อ · ไม่ล็อกการไปต่อ

## 4. เป้ารายสัปดาห์ (`weekProgress`)
วันที่ทำเซสชันจบอย่างน้อย 1 ครั้ง (รวมเซสชันสั้น) นับ 1 วัน · ครบ 5 ใน 7 = สัปดาห์สำเร็จ · สตรีคนับเป็นสัปดาห์ และ**สัปดาห์ปัจจุบันที่ยังไม่ครบไม่ตัดสตรีค**จนกว่าจะจบสัปดาห์

## 5. การวัดผล

### 5.1 ความยากของข้อ
ไม่มีข้อมูลผู้ใช้ตอนเปิดตัว จึงใช้ค่าที่ผู้เขียนกำหนด: ระดับคอร์ส (a2 b1 b2 c1) × `level` 1–3 · เมื่อข้อใดมีคนทำ ≥ 50 ครั้ง ระบบรายงานข้อที่อัตราถูกครั้งแรกต่ำกว่า 25% หรือสูงกว่า 95% ให้คนตรวจ (**ไม่ปรับอัตโนมัติ**) และข้อที่ตัวหลอกตัวใดถูกเลือกมากกว่าข้อถูก (สัญญาณว่าเฉลยอาจผิดหรือโจทย์กำกวม)

### 5.2 แบบวัดระดับฟรี (`placementEstimate`)
- 25 ข้อชุดเดียวคงที่ 20 นาที: A2 6 · B1 8 · B2 7 · C1 4 ข้อ กระจายไวยากรณ์ ศัพท์ อ่าน สนทนา · ตรวจที่เซิร์ฟเวอร์ เฉลยไม่ลงเครื่อง
- **ผ่านระดับ** = ถูก ≥ 60% ของข้อระดับนั้น และผ่านทุกระดับที่ต่ำกว่าตามลำดับ (เดาสุ่ม 4 ตัวเลือกได้ราว 25% จึงตั้ง 60%)
- ตำแหน่งในระดับ: ทำข้อของระดับถัดไปได้ ≥ 35% = "ช่วงบน" ไม่ถึง = "ช่วงล่าง"
- คอร์สที่แนะนำ:

| ผล | แนะนำ |
|---|---|
| ช่วงบนของระดับ X | คอร์สระดับถัดไป 1 รอบ |
| ช่วงล่างของ X และผ่าน X แบบแน่น (≥ 80%) | คอร์สระดับถัดไป โดยบอกตรง ๆ ว่าอาจต้อง 2 รอบ |
| ช่วงล่างของ X และผ่าน X ไม่แน่น | คอร์สระดับ X ก่อน แล้วระดับถัดไป (ชุด "ทุกคอร์ส") |
| ยังไม่ผ่าน A2 | คอร์ส a2 (ทำข้อ A2 ได้ < 35% = อาจต้อง 2 รอบ) |
| ผ่านถึง C1 | คอร์ส c1 เพื่อซ้อมรูปแบบ |

- **ก้ำกึ่ง** (`borderline`): ขาดหรือเกินขั้นต่ำเพียง 1 ข้อ → หน้าเว็บเขียน "อยู่ระหว่าง ... กับ ..." เพราะแต่ละระดับมีแค่ 4–8 ข้อ ความคลาดเคลื่อนสูง · ทุกผลใช้คำว่า "โดยประมาณ"
- แบบปรับตามความสามารถ (2 ขั้น) ทำเมื่อมีข้อที่มีข้อมูลจริง ≥ 150 ข้อ ไม่ทำตอนเปิดตัว

### 5.3 ชุดวัดผล 3 ครั้ง
- **ทั้ง 3 ชุดครอบคลุมหัวข้อของทั้งคอร์ส 12 สัปดาห์** ไม่ใช่เฉพาะที่เรียนแล้ว มิฉะนั้นคะแนนเทียบกันไม่ได้ · ครั้งที่ 1 จึงต่ำเป็นปกติ และหน้าเว็บต้องบอกก่อนเริ่มว่า "ชุดนี้มีเรื่องที่ยังไม่ได้เรียน เพื่อให้เห็นว่าเพิ่มขึ้นเท่าไรเมื่อจบคอร์ส"
- ชุดคู่ขนาน 3 ชุดต่อคอร์ส ชุดละ 40 คะแนน 40 นาที สร้างจาก**ตารางเดียวกัน** (จำนวนข้อเท่ากันทุกช่อง หัวข้อ × `level`) · ลำดับชุดที่ผู้เรียนแต่ละคนได้หมุนตามรหัสผู้ใช้ (คนที่ 1 ได้ ก-ข-ค คนที่ 2 ได้ ข-ค-ก ...) เพื่อให้ความต่างของความยากระหว่างชุดไม่ปนกับพัฒนาการ และภายหลังใช้ข้อมูลนี้เทียบความยากของชุดได้
- ระหว่างทำ**ไม่ส่งเฉลย**ลงเครื่อง ส่งคำตอบทั้งชุดแล้วจึงได้เฉลยและเหตุผล

### 5.4 ความพร้อมรายทักษะ (`readiness`)
- ค่า = 60% จากชุดวัดผลล่าสุดของทักษะนั้น + 40% จากอัตราถูก**ครั้งแรก**ของข้อระดับเป้าหมายใน 14 วัน (ไม่นับการทบทวนซ้ำ) · มีข้างเดียวก็ใช้ข้างนั้น
- ข้อมูลรวมน้อยกว่า 20 ข้อ = "ข้อมูลยังไม่พอ" ไม่แสดงแถบ
- ≥ 70 "อยู่ในช่วงเป้า" · 55–69 "ใกล้เป้า" · ต่ำกว่า "ยังห่างเป้า"
- **เกณฑ์ 70 เป็นค่าตั้งต้นที่ยังไม่มีหลักฐานรองรับ** วิธีเดียวที่จะรู้ว่าตรงกับผลสอบจริงคือถามผู้เรียนหลังสอบ: หน้า "สอบแล้ว" ให้กรอกระดับที่ได้แบบสมัครใจ (ไม่ต้องแนบหลักฐาน) แล้วเทียบกับความพร้อมก่อนสอบ · เมื่อมีสัก 50 ราย จึงปรับเกณฑ์และเขียนในเว็บได้ว่าเกณฑ์มาจากอะไร ก่อนหน้านั้นใช้ข้อความ "ประเมินจากแบบฝึกของเรา ไม่ใช่ผลสอบ" ทุกที่

### 5.5 ข้อรับรองความคุ้มค่า (`guaranteeEligible`)
เซสชันเต็มที่ทำจบ ÷ 60 ≥ 80% (เซสชันสั้นไม่นับ) + ทำชุดวัดผลครบ 3 ครั้ง + ครั้งที่ 3 ต่ำกว่า 70% → เซิร์ฟเวอร์ต่ออายุให้เอง 3 เดือนและแจ้งในหน้าผล ผู้เรียนไม่ต้องยื่นคำขอ

## 6. เซิร์ฟเวอร์กับเครื่องผู้เรียน
- **เฉลยอยู่ที่ไหน:** แบบวัดระดับฟรีและชุดวัดผล = ตรวจที่เซิร์ฟเวอร์ · เซสชันและฝึกเพิ่มของผู้มีสิทธิ์ = ส่งข้อพร้อมเฉลยและเหตุผลลงเครื่องทั้งเซสชัน เพื่อให้เฉลยขึ้นทันทีและเน็ตหลุดกลางคันไม่เสียงาน (ผู้เรียนจ่ายแล้ว ความเสี่ยงคือการดูดทั้งคลัง ซึ่งกันด้วยเพดานข้างล่าง ไม่ใช่การซ่อนเฉลย)
- **เพดานต่อผู้ใช้ต่อวัน:** 6 เซสชัน · ฝึกเพิ่ม 60 ข้อ · ข้อไม่ซ้ำรวม 200 ข้อ · เกินแล้วแสดง "ครบโควตาวันนี้" (ผู้เรียนจริงไปไม่ถึง: จังหวะเร่งคือ 2 เซสชัน)
- **บันทึกแบบเหตุการณ์:** เครื่องผู้เรียนเก็บคำตอบเป็นรายการเหตุการณ์ `{eid, item, correct, first, mode, ts}` ในเครื่องก่อน แล้วส่งเป็นชุดไป `exam-api/sync` · เซิร์ฟเวอร์รับซ้ำได้ (กันซ้ำด้วย `eid`) และเป็นผู้คำนวณสถานะข้อ ความคืบหน้า และความพร้อมด้วย engine ตัวเดียวกัน แล้วส่งสถานะล่าสุดกลับ · สองเครื่องใช้พร้อมกันได้ เซิร์ฟเวอร์คือความจริง
- **จุดเรียก (ร่างสัญญา):**

| จุดเรียก | ต้องมีสิทธิ์ | ทำอะไร |
|---|---|---|
| `POST exam-api/placement/grade` | ไม่ | รับคำตอบ 25 ข้อ คืนผลตาม 5.2 (จำกัดอัตราต่อ IP) |
| `GET exam-api/home` | ใช่ | สถานะวันนี้: ตัวชี้ เป้าสัปดาห์ ความพร้อม จำนวนข้อถึงกำหนด วันจบ |
| `GET exam-api/session?kind=full\|short\|extra` | ใช่ | ประกอบเซสชันตามข้อ 3 พร้อมเฉลย |
| `POST exam-api/sync` | ใช่ | รับเหตุการณ์ คืนสถานะ |
| `GET exam-api/checkpoint?n=1..3` · `POST .../submit` | ใช่ | ชุดวัดผลตาม 5.3 |
| `POST exam-api/report` | ไม่ | รายงานข้อผิด |
| `exam-billing/status · checkout · verify` | ล็อกอิน | ราคา สั่งซื้อ ยืนยันการจ่าย |

## 7. สิ่งที่ยังเป็นสมมติฐาน (ต้องดูข้อมูลจริงแล้วปรับ)
เกณฑ์ผ่าน 60% และช่วงบน 35% ของแบบวัดระดับ · เกณฑ์ความพร้อม 70/55 และน้ำหนัก 60/40 · ระยะทบทวน · เพดานทบทวน 8 ข้อ (ถ้าผู้เรียนสะสมข้อถึงกำหนดเกิน 24 ข้อเป็นประจำ แปลว่าข้อยากเกินหรือเพดานต่ำเกิน) · ความเทียบเท่าของชุดวัดผล 3 ชุด
