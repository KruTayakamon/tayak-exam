**สถานะ: เขียนเป็นไฟล์แล้วทั้งหมด ยังไม่ได้รันกับฐานข้อมูลจริง ยังไม่ได้ deploy**

## 2. การตัดสินใจหลัก
1. **แยกจากเกมครัวเด็ดขาดในฐานเดียวกัน:** ใช้ `auth.users` ร่วมกันอย่างเดียว ไม่อ่านไม่เขียนตารางของเกมครัว และมีเทสต์บังคับ · ลบตาราง `exam_*` ทั้งหมดทิ้งได้โดยเกมครัวไม่กระทบ
2. **เบราว์เซอร์อ่านเนื้อหาที่ขายตรง ๆ ไม่ได้:** `exam_items` และ `exam_course_weeks` ไม่มี policy จึงเข้าถึงได้เฉพาะ Edge Function ซึ่งตรวจสิทธิ์ก่อน · ตารางของผู้เรียนเอง (สิทธิ์ คำสั่งซื้อ ความคืบหน้า) อ่านได้เฉพาะเจ้าของ และ**เขียนได้เฉพาะเซิร์ฟเวอร์** ผู้เรียนแก้ความคืบหน้าหรือสิทธิ์ของตัวเองไม่ได้
3. **เซิร์ฟเวอร์ตรวจคำตอบเอง:** เครื่องผู้เรียนส่ง "ตอบอะไร" ไม่ได้ส่ง "ถูกหรือผิด" · "ตอบครั้งแรก" ตัดสินจากประวัติในฐานข้อมูล → ความพร้อม ข้อรับรอง และเงื่อนไขคืนเงินจึงปลอมจากเครื่องไม่ได้
4. **สิทธิ์เป็นรายสินค้า มีวันหมดอายุ:** `cefr-<คอร์ส>` หรือ `cefr-all` · ซื้อซ้ำบวกต่อจากวันหมดอายุเดิม · ต่อเวลา 3 เดือนใช้ได้เมื่อเคยมีสิทธิ์นั้นและหมดไปไม่เกิน 90 วัน · ข้อรับรองความคุ้มค่าเซิร์ฟเวอร์ต่อให้เองตอนส่งชุดวัดผลครั้งที่ 3 ครั้งเดียวต่อสิทธิ์
5. **ราคาเปิดตัว:** ใช้อยู่จนกว่าบอสกำหนดวันสิ้นสุดใน `RULES.launch_until` (ตอนนี้ไม่มีวันสิ้นสุด) · หน้าเว็บห้ามเขียนว่า "เหลืออีก N วัน" จนกว่าจะมีวันจริง
6. **ไม่พึ่ง webhook ของ Beam:** ให้สิทธิ์ตอนผู้ซื้อกลับจากหน้าจ่าย และทุกครั้งที่เปิดหน้าบัญชี โดยถาม Beam ตรง ๆ → ไม่ต้องแตะฟังก์ชัน `beam-webhook` ของเกมครัว · ข้อเสีย: ถ้าผู้ซื้อจ่ายแล้วปิดเบราว์เซอร์ทันที สิทธิ์จะมาเมื่อเปิดเว็บครั้งถัดไป (ยอมรับได้)
7. **คืนเงินทำด้วยมือ:** หน้าบัญชีแสดงว่าคำสั่งซื้อใดยังอยู่ในเงื่อนไขคืนเงิน (7 วัน ไม่เกิน 3 เซสชันเต็ม) ผู้เรียนติดต่อทาง LINE OA บอสโอนคืนแล้วรันคำสั่งเพิกถอนสิทธิ์ (หัวข้อ 5) · ไม่มีปุ่มคืนเงินอัตโนมัติ เพราะ Beam ต้องทำจากแดชบอร์ด
8. **แบบวัดระดับไม่ต้องล็อกอิน:** จำกัด 5 ครั้งต่อชั่วโมงต่อ IP โดยเก็บเฉพาะแฮชของ IP ผสมเกลือลับ (`EXAM_IP_SALT`) ไม่เก็บ IP จริง
9. **เพดานต่อวันกันดูดคลัง:** 6 เซสชันต่อวันต่อผู้ใช้ (ค่าใน `engine/config.json`)

## 3. ข้อมูลส่วนบุคคลที่เก็บ (ต้องตรงกับนโยบายความเป็นส่วนตัวที่จะเขียน)
| ข้อมูล | ที่เก็บ | เหตุผล | ลบได้โดย |
|---|---|---|---|
| อีเมลจาก Google | `auth.users` (ใช้ร่วมกับเกมครัว) | ล็อกอิน ผูกสิทธิ์ | ลบบัญชี |
| คำตอบ สถานะทบทวน เซสชัน ชุดวัดผล แผนเรียน | `exam_events` `exam_item_state` `exam_sessions` `exam_checkpoints` `exam_enrolments` | ทำงานของคอร์ส | ปุ่ม "ลบข้อมูลการเรียนของฉัน" (`exam_delete_my_data()`) |
| คำสั่งซื้อและสิทธิ์ | `exam_orders` `exam_entitlements` | หลักฐานการซื้อ | เก็บตามหน้าที่ทางบัญชี |
| ผลแบบวัดระดับ + แฮช IP | `exam_placements` | แสดงผล จำกัดอัตรา | แฮช IP ควรลบเมื่อครบ 30 วัน (งานประจำ ยังไม่ได้ตั้ง) |
| ผลสอบจริงที่แจ้งเอง | `exam_self_reports` | ปรับเกณฑ์ความพร้อม (สมัครใจ) | ปุ่มลบข้อมูล |

ไม่เก็บ: ชื่อจริง เบอร์โทร โรงเรียน เสียงที่อัด (อยู่ในเครื่องผู้เรียน) งานเขียน (อยู่ในเครื่องผู้เรียน)
⚠️ ผู้ใช้ของเกมครัวและของ CEFR for Kru อยู่ในตารางผู้ใช้เดียวกัน นโยบายความเป็นส่วนตัวของทั้งสองเว็บต้องบอกเรื่องนี้

## 4. สิ่งที่บอสต้องทำเมื่ออนุมัติ (ตามลำดับ)
1. อ่านหัวข้อ 2 และ 3 ถ้าเห็นด้วย แจ้ง "อนุมัติ SQL"
2. เปิด Supabase โปรเจกต์ `tayak-kitchen` → SQL Editor → วางเนื้อหา `supabase/sql/2026-11-16_exam_core.sql` → Run (ผลที่ควรได้: Success ไม่มีแถวคืน)
3. Authentication → URL Configuration → เพิ่ม URL ของเว็บใหม่ใน Redirect URLs (ยังไม่มีจนกว่าจะสร้างโปรเจกต์ Cloudflare Pages ของเว็บนี้)
4. Edge Functions → Secrets เพิ่ม `EXAM_SITE_URL` (ที่อยู่เว็บใหม่) และ `EXAM_IP_SALT` (ข้อความสุ่มยาว ๆ อะไรก็ได้) · `BEAM_MERCHANT_ID` `BEAM_API_KEY` ใช้ของเกมครัวที่ตั้งไว้แล้วได้ ถ้าจะรับเงินเข้าบัญชี Beam เดียวกัน
5. แจ้ง Claude ให้ deploy ฟังก์ชัน `exam-api` และ `exam-billing` (หรือบอส deploy เอง) แล้วทดสอบตามหัวข้อ 6

## 5. คำสั่งที่บอสใช้เป็นครั้งคราว (รันใน SQL Editor)
```sql
-- ให้สิทธิ์ฟรีกับทีมงานหรือผู้ทดสอบ (แก้อีเมล สินค้า และจำนวนวัน)
insert into public.exam_entitlements (user_id, product, expires_at, source)
select id, 'cefr-all', now() + interval '365 days', 'comp' from auth.users where email = 'someone@example.com'
on conflict (user_id, product) do update set expires_at = excluded.expires_at, source = 'comp', updated_at = now();

-- เพิกถอนสิทธิ์หลังโอนเงินคืนแล้ว (แก้รหัสคำสั่งซื้อ)
update public.exam_orders set status = 'refunded', refunded_at = now() where id = '<order id>';
delete from public.exam_entitlements e using public.exam_orders o
 where o.id = '<order id>' and e.user_id = o.user_id and e.product = coalesce(o.target, o.product);

-- อ่านรายงานข้อผิดล่าสุด
select created_at, item_id, why, note from public.exam_reports order by created_at desc limit 50;
```

## 6. การทดสอบหลัง deploy (ยังไม่ได้ทำ)
1. Beam playground: สร้างคำสั่งซื้อ `cefr-b1` → จ่ายทดสอบ → กลับมาแล้วได้สิทธิ์ 180 วัน · กด verify ซ้ำไม่ได้วันเพิ่ม
2. ผู้ไม่มีสิทธิ์เรียก `session` ได้ 403 · เรียกตาราง `exam_items` ตรงจากเบราว์เซอร์ได้ 0 แถว
3. ทำเซสชันวันที่ 1 จบ → ตัวชี้เป็นวันที่ 2 · ข้อที่ผิดมีกำหนดพรุ่งนี้ · ส่งเหตุการณ์ชุดเดิมซ้ำแล้วไม่นับซ้ำ
4. แบบวัดระดับ: ส่งคำตอบได้ผล ไม่มีเฉลยในคำตอบของเซิร์ฟเวอร์ · ครั้งที่ 6 ในหนึ่งชั่วโมงได้ 429
5. ชุดวัดผล: ก่อนส่งไม่มีเฉลย หลังส่งมีเฉลยและคะแนนรายทักษะ

## 7. งานที่เหลือของหลังบ้าน (ผู้ที่มาทำต่อทำได้)
- เลือกข้อของชุดย่อยวันที่ 6 ในเส้นทาง `session` (ตอนนี้ส่งแค่สเปกของชุดย่อย ยังไม่ได้เรียก `pickMock`) และเซสชันซ่อม
- โหมด `extra` (ฝึกเพิ่มตามทักษะ สมุดข้อผิด) พร้อมเพดาน 60 ข้อต่อวัน
- งานประจำลบแฮช IP ที่เก่ากว่า 30 วัน
- รายงานคุณภาพข้อจากข้อมูลจริง (ข้อที่ถูกน้อยกว่า 25% หรือตัวหลอกถูกเลือกมากกว่าข้อถูก)
- ข้อของแบบวัดระดับต้องมีฟิลด์ `band` (a2 b1 b2 c1) ใน body: เพิ่มในรูปแบบไฟล์ `bank/cefr/placement.yaml` และตัวตรวจ
